Lec1 (Sec1):
Visual Learning Outcome: A fully illuminated linear path from top to bottom.
Corrects misconception: Demonstrates that execution order is the primary organizational principle rather than data ownership.
1. THE SOFTWARE LAYER:
A 3D vertical track (rendered as a glowing pipe geometry in Three.js) representing the execution path. Instruction blocks ("Step 1: Calculate", "Step 2: Print", "Step 3: Save") are floating 3D glass panels aligned along the Z-axis. An interactive slider controls playback speed. A glowing progress cylinder grows down the track.
2. THE MEMORY TOPOLOGY (RAM) LAYER:
Stack Frame: process() [size: 16 bytes]. Local variable 'double area' occupies 8 bytes at offset -8 from Base Pointer RBP. Heap: Unused (0 bytes). Dynamic allocs: None. Stack grows downwards when process() is called and shrinks upwards when it returns.
3. THE CPU & REGISTERS LAYER:
Program Counter (RIP) moves sequentially: 0x00401010 -> 0x00401025 -> 0x0040103E. Instruction Pointer register ($RIP$) increments sequentially by 4 bytes ($$\Delta RIP = +4$$). ALU performs floating-point multiplication in XMM0 register ($$Area = \pi \times r^2$$).
4. THE GPU / VRAM LAYER:
Three.js creates a 3D scene. The procedural flow track and pointer are drawn as 3D pipe geometries. Vertex buffers (VBOs) store the geometries of the 3D track and glass panels. A custom fragment shader renders the active instruction with a glowing neon border ($0.0, 1.0, 0.0$ emission) and streams glowing line primitives to represent data flow.
5. UNDER-THE-HOOD CORRECTOR:
In procedural programming, there are no hardware-enforced boundaries. Variables on the stack are simple memory locations. Any instruction with the correct address offset can read or write to them, as memory safety is purely a compiler-level concept.
